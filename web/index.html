Your workspace. Your flow.

Klyvera is an original Linux desktop for developers. Each project gets a Space: its own paths, apps and layout. Switching projects switches the environment with it.

01 / The friction

Switching projects should switch everything.

Developers do not only switch tasks. They rebuild context: editor roots, terminals, app windows and window layouts. Klyvera makes that context a first-class object.

01

Context is rebuilt by hand.

Every project starts with the same folder, terminal and window ritual. The desktop remembers none of it.

02

Settings drift.

App choices and layout hints live in memory or scattered notes, not with the project they belong to.

03

Trust is implicit.

A workspace profile downloaded from the internet should not be allowed to run commands without a clear confirmation.

Read the Spaces specification

Concept and prototype work, not a shipped release.

02 / Spaces

A project becomes a place.

A Space stores the project path, the apps you need and optional layout hints. Opening it is one action, not ten.

  • Project paths stay explicit. Roots are validated; traversal is rejected.
  • Apps launch as argv arrays. No shell strings, interpolation or silent execution.
  • Layout hints travel with the Space. Workspace placement is data, not a script.
  • Imported profiles stay untrusted. A profile hash must be confirmed before commands run.

03 / Shell

A shell that stays out of the way.

Launcher, notifications and control center share one visual language and one keyboard model. Failures stay visible instead of being replaced by invented data.

  • Keyboard first. Search, select, confirm and dismiss without a pointer.
  • Honest states. Unavailable services show a degraded state, not a fake reading.
  • Local by default. Core surfaces need no account, server or network.

Launcher

Fuzzy app, Space and settings search with recent items and full keyboard selection.

Spaces

List and detail views, a three-step editor, inline validation and explicit trust confirmation.

Control center

Appearance, display, audio, network, Bluetooth, power, shortcuts and about in one surface.

Measured honesty

Service failures degrade visibly. The status page separates local checks from target work.

04 / Design

A system, not a skin.

Every colour, space, radius and motion step comes from one token source. Themes are generated from that source, not hand-painted separately.

  • Themes

    Dark, light and high contrast, with matched semantic tokens.

  • Contrast

    47 required WCAG AA pairs per theme; 0 failures in the local report.

  • Type

    Heading and UI stacks prefer Manrope and Inter. No web fonts are downloaded.

  • Icons

    Klyvera Line, an original 1.75 px stroke set. No third-party icon files.

  • Motion

    Short, functional transitions. Reduced-motion removes them.

05 / Status

What is real, and what is next.

Klyvera is a prototype. This summary is deliberately narrower than the vision: it separates work that has run here from work that still requires an Arch target.

Verified locally

Checks that passed

  • 75 Rust tests pass in the workspace.
  • 9/9 schema checks pass, including invalid documents.
  • 47/47 required WCAG AA pairs pass in each theme.
  • 3 Arch packages built and smoke-installed in a container.
Unverified on target

Still needs Arch

  • Live Hyprland and Quickshell session behaviour.
  • ISO build, boot, autologin and installer.
  • Dependency-resolved package installation.
  • CI workflow execution on GitHub.
Prototype limits

No launch claims

  • No release, signed packages or supported installer.
  • Product visuals are illustrations with sample data, not a live session.
  • The license awaits maintainer confirmation.
  • No telemetry is implemented, by design.
