Overview

Klyvera is an original, local-first Linux desktop for developers and technical users. It pairs a calm, keyboard-first shell with project-based workspaces called Spaces. A Space carries a project path, the applications it needs, and optional layout hints.

The target is Arch Linux with Hyprland on Wayland, Quickshell and Qt 6 QML for the shell, and Rust for core services. The project runs offline, has no accounts, and includes no telemetry.

Prototype. Klyvera has not run in a live Hyprland session on Arch yet. The ISO is not built, and packages are not signed. Read the status section before treating any surface as production-ready.

Architecture

The project keeps presentation, product logic and system integration separate. Pure QML pages do not import Quickshell; target access lives behind a data contract.

Spaces

A Space is persisted JSON with a schema version. It stores a project path, optional applications, optional commands and layout hints. Import and export use the same validated model.

  • Paths are validated. Project roots must exist, and traversal is rejected.
  • Commands are argv arrays. Shell interpreters are rejected; nothing is passed through a shell string.
  • Working directories stay inside the project. A command cannot point at an arbitrary parent path.
  • Imports are untrusted. Command execution requires a confirmation stored against the profile hash.
  • Layout hints are data. Workspace placement is not a script and is not applied on the development machine.

Read the Spaces specification or the JSON Schema.

Security model

Profiles are treated as untrusted input, not as scripts. The core enforces limits before anything reaches process launch.

  • No shell execution. Processes are launched from argv arrays resolved through installed desktop entries.
  • Explicit trust. Imported commands require a recorded confirmation tied to the profile hash.
  • Private state. Runtime directories are created with 0700; sensitive files use 0600.
  • Local IPC. The daemon binds a Unix socket in XDG_RUNTIME_DIR with same-UID peer checks and a versioned JSON protocol.
  • Atomic writes and backups. Config writes are atomic; restore verifies a manifest and creates a pre-restore backup.

See SECURITY.md for reporting and the full invariants.

Design system

design/tokens.json is the only visual source of truth. It generates shell/styles/Theme.qml, web/src/styles/tokens.css and the contrast report. Generated files must not be edited by hand.

The system ships dark, light and high-contrast palettes with semantic roles for surfaces, text, accents, focus, borders, elevation and motion. The local contrast report verifies 47 required WCAG AA pairs per theme with zero failures. 

python3 design/generators/generate.py --check

Read docs/design-system.md for component contracts and responsive rules.

Build from source

The site and core checks run on a Debian-based workstation. Hyprland, Quickshell and mkarchiso require the Arch target.

Requirements: Rust stable, Python 3, Node.js 20.19+ or 22.12+, and a POSIX shell. Qt 6 is needed only for the offscreen preview and QML lint when available. 

git clone https://github.com/nurlancoder/Klyvera.git
cd Klyvera
./scripts/check.sh

Build the website separately:

cd web
npm ci
npm run build

Do not install system packages or run Klyvera as root. The daemon is a user service. See packaging/systemd/klyvera-daemon.service.
